## 一、服务器选型：你的中转站到底该放哪里

建中转站的第一步不是装软件，是选服务器。位置选错，后面所有事都白搭。

### 1.1 先搞清楚一个核心问题：香港能不能中转 GPT/Claude？

**不能直接用。**

2024 年 7 月起，OpenAI 正式把香港列入了禁止地区。你把 One API 部署在香港服务器上，服务器的请求打到 `api.openai.com`，OpenAI 看到来源 IP 是香港地址，直接拒绝。同样，Anthropic (Claude) 也对香港 IP 做了限制。

所以一条铁律：**香港服务器不能直接转发 OpenAI / Anthropic API 请求。**

那为什么很多中转站还在用香港？

因为中转站的架构是两层的——香港节点只做"接客"，不做"出站"：

```
国内用户 → 香港节点（接请求，延迟 10ms）
            → 新加坡/日本节点（实际调 OpenAI API）
            → 结果回传给香港节点 → 返回国内用户
```

香港只当入口，出站转发到**新加坡**——新加坡 IP 不在任何封禁名单里，是所有中转站做 GPT/Claude 出站的标准选择。

如果只做国产模型中转（DeepSeek / 通义 / Kimi），香港节点调国内模型不存在限制，一台香港服务器搞定所有事。

### 1.2 节点位置怎么选

| 国内→GPT/Claude（双节点方案） | **香港接 + 新加坡转** | 香港给用户的延迟更低（10-30ms），新加坡做转发，体验最优 | ¥100-250 |

## 二、搭建商用中转站：完整操作手册

### 2.1 基础设施

选好服务器之后，基础四件套：

| 项目 | 推荐 | 月费用 |
|---|---|---|
| 服务器 | 见上方推荐 | ¥50-150 |
| 域名 | 阿里云/腾讯云国际域名 | ¥10-20（分摊） |
| SSL 证书 | Let's Encrypt 免费 | ¥0 |
| 上游 Key | 官方采购或从大平台批发 | 按量计费 |

### 2.2 部署 One API（稳定可靠版）

One API 是 JustSong（songquanpeng）维护的老牌开源方案，GitHub 24k+ Star，生态最成熟、踩坑文档最多、承受了最大范围的生产验证。

```bash
# 一键部署
docker run --name one-api -d --restart always \
  -p 3000:3000 \
  -v /home/ubuntu/one-api/data:/data \
  -e SQL_DSN="oneapi.db" \
  -e SESSION_SECRET="$(openssl rand -base64 32)" \
  -e TZ=Asia/Shanghai \
  justsong/one-api
```

**初始化配置（手把手）：**
1. 浏览器访问 `http://你的IP:3000`，首次注册即为管理员
2. 进入「渠道」→ 添加你的上游 API（OpenAI / Anthropic / DeepSeek / 通义等），填 Key，设倍率
3. 进入「令牌」→ 生成用户访问令牌，支持额度限制和模型白名单
4. 进入「设置」→ 配置 SMTP 发信，开通用户自助注册

**Nginx 反代 + HTTPS（生产环境必配）：**

```nginx
server {
    listen 443 ssl;
    server_name api.你的域名.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 300s;
        proxy_buffering off;  # 流式响应必配
    }
}
```

### 2.3 部署 New API（功能增强版）

New API 是 One API 的社区 Fork，GitHub 8k+ Star，增加的核心功能：

```bash
# 部署 New API
docker run --name new-api -d --restart always \
  -p 3000:3000 \
  -v /home/ubuntu/new-api/data:/data \
  -e SQL_DSN="newapi.db" \
  -e SESSION_SECRET="$(openssl rand -base64 32)" \
  -e TZ=Asia/Shanghai \
  ghcr.io/songquanpeng/new-api:latest
```

New API 相对 One API 新增的功能包括：
- **Midjourney 支持**——可以卖 MJ 绘图，这是 One API 没有的
- **内置易支付**——支付宝/微信支付一键对接，One API 只有充值码
- **GPTs 通配符支持**——`gpt-4-gizmo-*` 自动匹配所有 GPTs
- **UI 美化**——管理面板更现代化

### 2.4 接入支付

- **New API**：内置易支付对接，后台配好商户接口就行
- **One API**：自带充值码系统。要对接真实支付，可以用插件或二次开发对接支付宝当面付
- **第三方方案**：自建支付网关 + One API 的 webhook 回调

### 2.5 Key 池管理的铁律

单条 Key 跑中转站等于把命交给别人——上游账号被封、限流、超支，你的用户全部跟着遭殃。

**正确姿势：**
- 准备 10-20 条上游 Key，分散在不同账号、不同渠道
- 每个账号设独立的日限额和月限额，防止单个账号超支
- 监控脚本每天检查 Key 余额，余额低于阈值自动告警
- 开 One API 的自动禁用：连续 429 错误超过阈值自动下线，手动恢复
- **不要在代码里硬编码 Key 池——用环境变量或配置中心管理**

## 四、主流商业中转平台全景图（2026实测）

2026 年市面上活跃的中转平台可以从几个维度来切分。

### 4.1 第一梯队：企业级全能平台

**① 星链 4SAPICOM**（4sapi.com）
- 定位：全场景企业级 AI 网关
- 核心数据：650+ 模型、综合降本 50-70%、SLA 99.99%、首 Token 延迟低至 20ms
- 技术底牌：CN2 GIA 专线 + MySQL 8.2 超高并发架构 + 多通道毫秒级容灾
- 特色：支持公对公开票、全量调用日志留存 180 天、子账号精细权限管控
- 适用对象：**企业级生产环境首选**，SaaS 服务商、中大团队

**② 诗云API**（ShiyunApi）
- 定位：企业级 AI API 承载层
- 核心数据：99.92% 稳定性、12 万 QPS 高并发、42 个边缘计算节点
- 技术底牌：香港/新加坡/东京全球边缘加速、HTTP3/QUIC 协议优化、多云冗余
- 适用对象：追求极致稳定性的企业级后端团队

### 4.2 第二梯队：垂直场景平台

**③ KoalaAPI**（koalaapicom）
- 定位：海外模型老牌中转服务商
- 核心数据：十年老牌、99.7% 调用成功率、国内节点延迟 50ms
- 特色：全流程对公发票、无最低消费、阶梯式优惠
- 适用对象：**中小团队商用开发**，海外模型常态化使用

**④ OpenRouter**（openrouter.ai）
- 定位：全球模型超市 + 动态比价路由
- 特色：200+ 模型、自动选最优价格线路、先买后付
- 短板：服务器在海外，国内直连延迟较高，支付仅限外卡或 Crypto
- 适用对象：模型调研、科研用途，**配合自建方案做备用路由**

**⑤ XingLianAPI**（xinglianapicom）
- 定位：国产化模型专属平台
- 核心数据：信创全适配、国产模型深度优化、等保三级认证
- 适用对象：政企单位、国企、国产化替代需求

### 4.3 第三梯队：个人/入门/性价比

**⑥ PoloAPI**
- 定位：性价比屠夫
- 特色：200+ 模型、倍率 0.3-0.8，价格最低的那一档
- 适用对象：个人开发者、预算敏感用户

**⑦ 硅基流动**（SiliconFlow）
- 定位：国产开源模型加速
- 特色：对 DeepSeek、Qwen 等国产模型深度优化，速度比官方还稳
- 适用对象：专注国产开源模型的开发者

**⑧ TreeRouter**（treeroutercom）
- 定位：学生/入门开发者
- 特色：学生认证后日均 10 万 Token 免费、全平台 9 折
- 适用对象：学生、AI 入门学习

**⑨ 云雾AI中转站**（yunwuai.cc）
- 定位：一站式 AI 接入
- 特色：宣称比官方低 30-50%，支持国内直连多模型

### 4.4 商业平台 vs 自建的决策

```
你是否有专职运维团队？
├─ 有
│  ├─ 数据安全要求极高 → One API / New API 自建
│  └─ 一般业务需求 → 自建（One API） + 商业平台做备用路由
└─ 没有
   ├─ 核心业务 → 直接买商业平台（4SAPI / ShiyunApi），省运维钱
   └─ 自用/小卖 → One API 自建，1 天搞定
```

**行业警示（CISPA 亥姆霍兹安全中心 2026 年 3 月报告）：**
- 调查 17 家中转站，近 50% 存在**模型替换**行为——你付 Claude Opus 的钱，实际跑的是国产小参数模型
- 部分平台**偷偷阉割上下文**——官方 200K 只给你 32K
- 你的每一条对话，中转站默认可以记录

**鉴别方法：**
1. 拿复杂推理题同时问官方和中转站，对比回答质量
2. 传一篇长文档让它总结中间某段，测真实上下文
3. 低于 0.5 倍率的基本是逆向接口（网页版额度拆卖）

## 五、「反向出海」——国产 Token 卖给国外用户

这是整个 Token 中转赛道里**最被低估**的新场景。

### 5.1 为什么有这个机会？

2026 年 2 月，中国大模型 Token 周调用量达到 4.12 万亿，历史上首次超越美国。全球调用量 Top 5 的模型中国占 4 席（MiniMax M2.5、Kimi K2.5、GLM-5、DeepSeek V3.2），全球占比 61%。

关键是**价格差距大得离谱**：

| 模型 | 输入（/百万Token） | 输出（/百万Token） | 相对 GPT-5.4 |
|---|---|---|---|
| GPT-5.4 | $10 | $40 | 基准 |
| Claude Opus 4.7 | $15 | $75 | 1.5-1.9x |
| DeepSeek V4 | **$0.3** | **$1.2** | **1/33** |
| 通义千问 3.6 | **$0.11** | **$0.44** | **1/90** |
| Kimi K2.5 | **$0.4** | **$1.6** | **1/25** |

国产模型在性能上已经对齐甚至部分超越海外竞品（DeepSeek V4 对标 GPT-5.4、GLM-5 对齐 Claude Opus 4.5），但价格只有 1/25 到 1/90。

**这催生了一个纯套利空间：**
- 海外开发者被 GPT / Claude 的高价逼疯了
- 他们想用 DeepSeek / Kimi / 通义，但没国内手机号、看不懂中文控制台、没有微信支付宝
- 你在美西/欧洲架节点，收他们的美元/Crypto，后端走国产模型的 Key
- 定价=国产原价×3-5，仍然比 GPT 便宜 90%

## 六、总结

2026 年的 Token 中转市场已经走出了"帮国内用户翻墙调 GPT"的草莽阶段，出现了三条清晰的分化路径：

| 路线 | 核心模式 | 服务器推荐 | 利润空间 | 适合谁 |
|---|---|---|---|---|
| **传统中转** | 国内→海外 GPT/Claude | 新加坡单节点（¥50-150/月） | 薄利，2-3 倍 | 有国内用户基础的站长 |

**▶ 新加坡是 GPT/Claude 中转最稳妥的节点**——不被封、延迟可控、稳定。香港只适合做入口层调国产模型，直接把香港当 GPT 中转站会使 OpenAI 封锁，必死。

**▶ 出海是最被低估的路线**——国产模型的价格优势和能力对齐，让"把 DeepSeek 卖给美国开发者"的利润率远超传统中转。
