# 分析数据需求规范 (Data Requirements Spec)

> 本文档定义每种分析类型的数据需求，由 agent 在分析前自行评估和补充。
> 这不是硬门控，而是清单——agent 对照检查，缺口自己补。

---

## 一、分析类型与数据需求矩阵

### 快速扫描 (Scan)
**场景**: 用户问"XX股票最近怎么样"，需要快速概览
**时间**: < 2 分钟
**置信度上限**: 50%

| 数据项 | 必要性 | 获取方式 | 缓存策略 |
|--------|--------|---------|---------|
| 实时行情（价/量/涨跌幅） | 必须 | `stock_client quote` | 5分钟 |
| 5日K线（判断短期方向） | 必须 | `stock_client kline 5` | 盘中30分钟 |
| PE/PB | 建议 | `stock_client finance` | 24小时 |
| 大盘指数 | 建议 | `stock_client market` | 1小时 |

### 标准分析 (Standard)
**场景**: 用户问"帮我分析下XX"，需要给出操作建议
**时间**: 3-5 分钟
**置信度上限**: 75%

| 数据项 | 必要性 | 获取方式 | 缓存策略 |
|--------|--------|---------|---------|
| 60日K线 | 必须 | `stock_client kline 60` | 1小时 |
| 实时行情 | 必须 | `stock_client quote` | 5分钟 |
| PE/PB/市值 | 必须 | `stock_client finance` | 24小时 |
| 大盘指数 | 必须 | `stock_client market` | 1小时 |
| 行业板块 | 必须 | `stock_client sector` | 1小时 |
| 资金流向 | 建议 | `stock_client flow` | 盘中30分钟 |
| 融资融券 | 可选 | `stock_client margin` | 24小时 |
| 近期新闻 | 建议 | 新闻搜索 | 按需 |
| 同行对比 | 建议 | 板块成分股行情 | 按需 |

### 深度分析 (Deep)
**场景**: 重大决策前（加仓/减仓/清仓），需要完整论证
**时间**: 5-10 分钟
**置信度上限**: 85%

| 数据项 | 必要性 | 获取方式 |
|--------|--------|---------|
| 标准分析全部 | 必须 | 同上 |
| 120日K线 | 必须 | `stock_client kline 120` |
| 周K线（52周） | 必须 | 需扩展 fast_data |
| 季度财报（最近4季） | 必须 | 巨潮/akshare |
| 行业排名（板块内位置） | 必须 | 板块成分股对比 |
| 历史新闻（30天） | 必须 | 新闻存档 |
| 大宗交易 | 建议 | akshare |
| 股东户数变化 | 建议 | akshare |

### 复盘验证 (Review)
**场景**: 每日收盘后验证昨日预测
**时间**: 2-3 分钟

| 数据项 | 必要性 |
|--------|--------|
| 昨日预测记录 | 必须 |
| 今日K线（含分时图特征） | 必须 |
| 大盘对比（相对强弱） | 必须 |
| 做T验证（是否触及区间） | 必须 |

## 二、数据缺口处理原则

### agent 自行判断流程

```
收到分析请求
    │
    ▼
识别分析类型（根据用户问题判断）
    │
    ▼
对照数据需求矩阵 → 检查本地缓存和数据
    │
    ├── 全部满足 → 开始分析
    │
    ├── 部分缺失但非必须 → 标记"数据不全"，降低置信度，继续分析
    │
    └── 必须项缺失 → 先拉数据，拉不到再降级
         │
         ├── 拉到 → 继续
         └── 拉不到 → 降级为低一级分析（比如 Deep→Standard）
                      明确告知用户缺了什么
```

### 降级规则

| 缺失项 | 影响 |
|--------|------|
| 缺60日K线（只有实时行情） | 降级为 Scan，置信度上限 30% |
| 缺基本面（PE/PB/财报） | 标注"纯技术面分析"，置信度上限 50% |
| 缺行业对比 | 标注"缺少行业验证"，置信度降 10% |
| 缺近期新闻 | 标注"分析不含消息面" |

## 三、数据积累机制

### 每次分析后自动更新

```
分析完成
    │
    ▼
┌─────────────────────────────┐
│ 写入股票档案 (data/watchlist/│
│   active/{code}/profile.md)  │
│                              │
│ 更新内容：                    │
│ • 最新分析日期                │
│ • 关键价位（支撑/阻力）        │
│ • 股性观察（波动率/量特征）     │
│ • 历史关键事件时间线           │
│ • 技术指标快照                │
│ • PE/PB 历史轨迹              │
│ • 量价关系模式                │
└─────────────────────────────┘
```

### 档案结构

```markdown
# {名称}({代码}) 股票档案

## 基本信息
- 行业: xxx
- 市值: xxx
- 流通市值: xxx
- PE/PB: xxx / xxx
- 融资融券标的: 是/否

## 关键价位（动态更新）
| 类型 | 价位 | 确认日期 | 确认次数 |
|------|------|---------|---------|
| 铁底 | 16.00 | 2026-05-11 | 5次 |
| 近期阻力 | 16.45 | 2026-05-06 | 2次 |
| 中期阻力 | 17.12 | 2026-04-10 | 1次 |

## 股性特征（积累≥10条后总结）
- 日均波动率: 1.2%
- 量能特征: 缩量到50万以下通常见底
- 盘中活跃时段: 10:00-10:30, 14:00-14:30
- 板块联动性: 强（与券商ETF相关系数0.85）

## 分析历史索引
| 日期 | 类型 | 结论 | 置信度 | 验证结果 |
|------|------|------|--------|---------|
| 2026-05-08 | Standard | HOLD | 70% | 待验证 |
| 2026-05-11 | Deep | HOLD | 75% | 待验证 |

## 关键事件时间线
| 日期 | 事件 | 影响 |
|------|------|------|
| 2026-04-27 | 放量201万跌至16.10 | 探底信号 |
| 2026-05-06 | 放量197万冲16.45回落 | 试盘 |

## 量价关系模式积累
（每次分析观察到的新模式追加到这里）
- [2026-05-11] 5次测试16.00未破 → 强支撑确认
- [2026-05-11] 缩量到103万是近期地量 → 做空动能衰竭
```

## 四、agent 的行为契约

分析前，agent 必须在回复中声明：

```
📊 分析类型: [Scan/Standard/Deep]
📋 数据完整度: [完整/部分缺失/不足]
   已获取: K线60日 ✓ / 行情 ✓ / 大盘 ✓ / 行业 ✓ / PE/PB ✓
   缺失: 资金流向（非必须）
🔒 置信度上限: 75%（基于数据完整度）
```

数据不足时：
```
⚠️ 以下数据未获取：K线仅5日、缺PE/PB
   降级为 Scan 分析，置信度上限 30%
   建议在盘中获取完整数据后做 Standard 分析
```

分析完成后，自动更新股票档案。
