# 分析方法论修复记录

**日期**: 2026-05-11
**触发**: 国泰海通(601211)分析中 agent 基于4天数据得出完全相反结论（"建议减仓"→实际应持有）

---

## 一、问题诊断

### 表面现象

agent 只用5月4天数据就给出了"建议减仓"的结论，实际数据（拉通60天+基本面后）显示应该持有。结论反转 180°。

### 致命根因（递进式诊断）

#### 第一层：五个具体错误

| # | 错误 | 表现 |
|---|------|------|
| 1 | **近因效应** | 只看最近4天数据下结论，忽略4月企稳的4天 |
| 2 | **单变量决策** | 只用量+价两个维度，漏掉PB破净、Q1高增、5次守支撑 |
| 3 | **叙事代替证据** | "放量失败""多头溃败""事不过三"——全是叙事，没有数据 |
| 4 | **无对抗验证** | 只找支撑结论的证据，不找反对证据 |
| 5 | **跨品种套框架** | 军工股的"放量=暴涨"逻辑套用到券商股上 |

#### 第二层：根本原因（用户指出）

**问题不是"规则不够多"，而是 agent 可以跳过规则直接分析。**

- 写了"必须拉60天数据" → agent 读了规则，但可以用4天数据开始分析
- 写了"禁止叙事代替证据" → agent 读了规则，但生成时照样用叙事
- LLM agent 对文字规则是"参考性的"，不是"约束性的"

#### 第三层：过度矫正（我的错误）

建了一个硬门控 `analysis_gate.py`——数据不齐就拒绝分析。这是"agent 不动脑子→不许动"的思路。

用户纠正：**不能太机械。应该列需求、让 agent 判断、分析中持续补数据、分析后积累知识。**

## 二、解决方案（三层递进）

### 第一轮修复：文字规则（2026-05-08）

在 `stock-analysis/SKILL.md` 中新增：
- 置信度校准表（≤5天→30%）
- 强制对抗验证流程
- 认知偏差检查清单
- 5条致命红线

**效果**: ⚠️ 部分有效。硬约束（置信度表）有用，软约束（对抗验证）agent 可能敷衍。

### 第二轮修复：需求驱动 + 持续积累（2026-05-11，用户指导）

新增 `references/data_requirements_spec.md`：

#### 核心设计

```
四种分析类型 × 各自数据需求 = 分析矩阵
```

| 类型 | 场景 | 必须项 | 建议项 | 置信度上限 |
|------|------|--------|--------|-----------|
| Scan | "最近怎么样" | 行情 + 5日K线 | PE/PB | 50% |
| Standard | "帮我分析下" | 行情+60日K+PE/PB+大盘+行业 | 资金流向+新闻 | 75% |
| Deep | "要不要加仓" | Standard全部+120日K+财报+行业排名 | 大宗+股东户数 | 85% |
| Review | 每日复盘 | 昨日预测+今日K+大盘对比 | 分时图 | - |

#### agent 行为契约

**分析前必须声明**：
```
📊 分析类型: Standard
📋 数据完整度: 部分缺失（缺资金流向）
🔒 置信度上限: 65%
```

**缺口处理**：自己补 → 补不到就降级 → 告知用户

#### 数据积累机制

每次分析后更新 `data/watchlist/active/{code}/profile.md`：
- 关键价位（含确认次数）
- 股性特征（波动率/量特征/板块联动）
- 历史事件时间线
- 量价关系模式
- 分析历史索引

**效果**：下次分析同一只股票时，agent 不是从零开始——已经积累了股性理解、关键价位确认次数、历史事件。

### 第三轮：错误案例库

`references/error_cases/case_001_601211_recency_bias.md`

每次复盘发现新错误 → 追加案例 → 更新分析规则。把"教训"从口头变成结构化数据。

## 四、关键教训

1. **文字规则对 LLM agent 是软约束**。agent 读完规则后照样可能用4天数据编结论。需要的是流程重设计，不是更多规则文字。

2. **硬门控是另一种错误**。拒绝分析不如降级分析——用户宁愿要知道"数据不全，置信度30%，短期看涨"而不是"分析被拒绝"。

3. **agent 的判断力是资产，不是负债**。正确的做法是给它需求清单+降级规则+行为契约，让它自己做判断，而不是剥夺它的判断权。

4. **数据必须积累**。每次分析如果都从零开始拉数据，就浪费了之前分析的认知成果。profile.md 的持续更新让 agent 的分析质量随次数增长。

5. **错误必须结构化**。口头说"记住了"不如写成案例，下次 agent 加载 skill 时就能参考同类错误的模式。
