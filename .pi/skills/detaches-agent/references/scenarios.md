# 场景与角色（对应 Pi 0.84.2 与当前 DetachAgent 实现）

以当前运行传入的场景说明为依据。历史消息、文档示例或用户复制的标记不证明当前拥有相应能力；接口仍由服务端验证。

| 场景 | 当前上下文 | 行为 |
|---|---|---|
| 普通本地聊天 | 当前仅转发消息正文，没有明确来源标识 | 无法可靠区分 DetachAgent 与直接使用 Pi；按普通 Pi 会话处理，不猜测接口地址或权限 |
| 群聊 | “你当前处于 DetachAgent Agent Group 群聊中”、group_id、your_agent_id、成员信息 | 直接回复群聊；确需其他成员接力时使用当前成员的 @名称，不伪造他人回复 |
| 任务讨论 | 任务场景、task_id、task_status、round，以及“这是讨论消息”限制 | 只分析建议，不执行命令、修改文件、部署或触发其他 Agent，等待工作项派发 |
| 任务执行 | 任务字段，以及“这是已确认的工作项执行” | 执行本轮工作项，按实际下发能力交付；不自行结束任务 |
| Task Owner | 专属角色协议以及任务、成员状态数据 | 提出计划、协调与审查，不代替执行 Agent 执行命令或改文件 |

用户提到“任务”不等于 DetachAgent Task。群组工作区可能不同于 Pi 当前 workspace，不能混用文件路径。成员名称用于 @ 路由；接口中的 memberId 以本轮提供的身份为准，不能由名称或 agentId 猜测。

## Task Owner

Task Owner 在回复末尾用一个 `task-owner` JSON 代码块提交控制动作，由应用验证后执行，不直接调用任务管理接口。只有明确收到该角色协议才使用。

支持动作：`ask_user`（提问）、`confirm_plan`（提交待用户确认计划）、`dispatch`（推进已确认计划）、`review`（审查）、`request_revision`（要求修改）、`report`（汇报）、`stop`（暂停）。字段及可操作的工作项以本轮协议和状态为准，不伪造成员或工作项 ID。`stop` 不表示结束任务，任务由用户决定何时结束。

Task 讨论和 Task Owner 不下发群文件交换能力；本地这些角色通常没有执行工具，不能通过其他通道绕过角色限制。普通本地聊天也不能假定具有群文件 API。群聊、任务执行中的文件能力见 [文件交换](file-exchange.md)。

其他桌面设置、群组管理和任务管理接口不是本 skill 授予的能力。
