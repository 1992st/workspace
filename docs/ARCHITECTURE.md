## 2. 核心设计原则

### 2.1 数据与决策分离

```
数据层（确定性）          决策层（智能性）
┌─────────────────┐      ┌─────────────────┐
│ 技术指标计算     │      │ LLM 综合分析    │
│ • MA/EMA        │      │ • 市场理解      │
│ • MACD          │─────▶│ • 事件解读      │
│ • RSI/KDJ       │      │ • 情绪判断      │
│ • 成交量分析    │      │ • 综合决策      │
└─────────────────┘      └─────────────────┘
       ↓                          ↓
   准确、可追溯              灵活、可解释
```

### 2.2 预测可验证

```
预测时                              验证时
┌──────────────┐                  ┌──────────────┐
│ 股票: 000001 │                  │ 股票: 000001 │
│ 时间: T日    │                  │ 时间: T+1日  │
│ 预测: 买入   │    ┌────────┐   │ 实际: +2.5%  │
│ 理由: ...    │───▶│ 对比   │◀──│ 结果: ✅正确 │
│ 置信度: 75%  │    └────────┘   │              │
└──────────────┘                  └──────────────┘
```

## 3. 模块设计

### 3.1 数据获取模块 (data/)

```
data/
├── market_data.py      # 大盘数据获取
├── stock_data.py       # 个股数据获取
├── sector_data.py      # 板块数据获取
├── news_data.py        # 新闻数据获取
└── data_validator.py   # 数据验证
```

**职责**:
- 从多个数据源获取数据
- 数据清洗和标准化
- 数据质量验证
- 本地缓存管理

### 3.2 分析模块 (analysis/)

```
analysis/
├── technical.py        # 技术指标计算
├── sector_analysis.py  # 板块分析
├── sentiment.py        # 情绪分析
└── report_generator.py # 报告生成
```

**职责**:
- 技术指标计算（纯代码，确定性）
- 板块热度分析
- 情绪指标计算
- 生成结构化分析报告

### 3.3 LLM 模块 (llm/)

```
llm/
├── client.py           # LLM API 客户端
├── prompts/            # Prompt 模板
│   ├── market_prompt.txt
│   ├── sector_prompt.txt
│   └── stock_prompt.txt
├── parser.py           # LLM 输出解析
└── validator.py        # 结果验证
```

**职责**:
- 多 LLM 支持（DeepSeek/GLM/Kimi）
- Prompt 工程优化
- 输出解析和结构化
- 结果合理性验证

### 3.4 预测与验证模块 (prediction/)

```
prediction/
├── predictor.py        # 预测生成
├── recorder.py         # 预测记录
├── verifier.py         # 预测验证
├── accuracy_tracker.py # 准确率追踪
└── ab_tester.py        # A/B 测试
```

**职责**:
- 生成预测记录
- 存储预测结果
- 次日自动验证
- 准确率统计
- A/B 测试管理

## 5. 扩展性设计

### 5.1 新数据源接入

```python
# 统一接口
class DataSource(ABC):
    @abstractmethod
    def fetch(self, symbol: str, start: date, end: date) -> DataFrame:
        pass
    
    @abstractmethod
    def validate(self, data: DataFrame) -> bool:
        pass

# 实现示例
class AkshareSource(DataSource): ...
class YahooSource(DataSource): ...
class TushareSource(DataSource): ...
```

### 5.2 新 LLM 接入

```python
# 统一接口
class LLMClient(ABC):
    @abstractmethod
    def analyze(self, prompt: str, context: dict) -> AnalysisResult:
        pass

# 实现示例
class DeepSeekClient(LLMClient): ...
class GLMClient(LLMClient): ...
class KimiClient(LLMClient): ...
```

## 6. 容错设计

### 6.1 数据获取失败

```
尝试数据源A ──▶ 失败 ──▶ 尝试数据源B ──▶ 失败 ──▶ 使用缓存数据
         │                           │
         └──────── 成功 ◀────────────┘
```

### 6.2 LLM API 失败

```
调用 DeepSeek ──▶ 失败 ──▶ 调用 GLM ──▶ 失败 ──▶ 回退到代码评分
           │                      │
           └────── 成功 ◀─────────┘
```

### 6.3 预测验证延迟

```
T日预测 ──▶ T+1日数据缺失 ──▶ 标记为待验证 ──▶ 数据恢复后补验证
```

## 7. 监控与日志

### 7.1 关键指标

| 指标 | 说明 | 告警阈值 |
|------|------|---------|
| 数据获取成功率 | 每日数据获取成功率 | < 95% |
| LLM API 成功率 | LLM 调用成功率 | < 90% |
| 预测验证率 | 已验证/总预测 | < 90% |
| 系统准确率 | 整体预测准确率 | < 50% |

### 7.2 日志分级

```
DEBUG   - 详细调试信息
INFO    - 正常流程记录
WARNING - 非致命错误（如数据源切换）
ERROR   - 致命错误（需要人工干预）
```
