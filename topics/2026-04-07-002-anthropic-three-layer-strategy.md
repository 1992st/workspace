## L2 证据评分

### 什么是 Anthropic 三层战略？

Anthropic正在构建一个**垂直整合但开放**的AI生态，三层分别是：

```
┌─────────────────────────────────────────────────────┐
│  Layer 3: 应用层 (Application Layer)                │
│  - Claude (消费端)                                   │
│  - Claude Code (开发者工具)                          │
│  - Claude Desktop (本地应用)                         │
├─────────────────────────────────────────────────────┤
│  Layer 2: 协议层 (Protocol Layer)                   │
│  - Model Context Protocol (MCP)                      │
│  - 连接AI与外部世界的"USB接口"                       │
├─────────────────────────────────────────────────────┤
│  Layer 1: 模型层 (Model Layer)                      │
│  - Claude 3系列 (Haiku/Sonnet/Opus)                 │
│  - 底层模型能力与API                                 │
└─────────────────────────────────────────────────────┘
```

### 与 OpenAI 的差异

| 维度 | Anthropic | OpenAI |
|------|-----------|--------|
| 模型层 | Claude系列 | GPT系列 |
| 协议层 | **MCP（开放标准）** | Function Calling（私有） |
| 应用层 | Claude + Claude Code | ChatGPT + GPTs |
| 战略重心 | **协议标准化** | **应用变现** |

## L3 深度复核

### 反证与边界条件

**可能的问题1：MCP是不是伪需求？**
- 当前MCP使用门槛高，需要开发背景
- 但路线图显示正在解决（分发发现、包管理、沙箱化）
- 类比：早期浏览器插件也很复杂，现在一键安装

**可能的问题2：开放协议是否削弱护城河？**
- MCP开放意味着竞争对手也能用
- 但Anthropic的算盘是：**成为基础设施比成为应用更持久**
- 类比：HTTP协议开放，但AWS受益最大

**可能的问题3：OpenAI为什么不跟进？**
- OpenAI的Function Calling生态已很成熟
- 转换成本可能太高
- 但这恰恰是Anthropic的窗口期机会

### 失败风险

| 风险类型 | 概率 | 影响 | 触发条件 |
|----------|------|------|----------|
| 标准化失败 | 中 | 高 | 远程认证方案迟迟无法落地 |
| 生态碎片化 | 高 | 中 | Google/微软推出竞争协议 |
| 开发者不买账 | 低 | 高 | 使用体验持续不佳 |

## L4 成稿决策

### 核心冲突

> Anthropic要用**开放协议**建立生态护城河，但开放本身可能削弱控制力。

### 推荐理由

1. **战略意义重大**：这是Anthropic从"模型公司"向"平台公司"转型的关键信号
2. **时机合适**：MCP路线图刚发布，市场还在消化理解
3. **影响面广**：涉及开发者、应用厂商、平台方三类受众

### 可选角度

- **A案（稳妥）**：介绍MCP是什么+路线图解读+对开发者的影响
- **B案（进攻）**：对比Anthropic vs OpenAI战略差异，分析谁会赢

**推荐B案**：有对比才有冲突，更容易引发讨论。

## 可执行动作（给读者的3条建议）

1. **如果你是AI应用开发者**：关注MCP的远程服务器支持进展，这可能让你无需自建基础设施就能接入各种工具能力。

2. **如果你是平台产品经理**：评估是否要支持MCP协议，早期支持可能获得生态红利，但需权衡与自研方案的冲突。

3. **如果你是技术决策者**：不要被"开放标准"迷惑，关注实际使用体验和社区活跃度，标准之战的赢家通常不是最早的那个。
