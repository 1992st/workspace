# Win_Stock 分析机制伤害审计 2026-05-22

## 结论

这次问题不是某一次分析写错，而是旧机制允许“数据不够时仍然输出强操作”。这会让用户误以为系统已经完成了数据核验、风险核验和反方审查，实际却可能只是把零散数据、缓存数据、新闻标题或主观推断组织成了完整报告。

机制真正伤人的地方：

1. 数据缺口没有强制阻断操作建议。
2. 账户风险未知时仍输出做T、加仓、止损、目标价。
3. “主力资金”“外资流向”“机构出货”等语言过强，但数据口径和时效经常没有写清。
4. 缓存、接口失败、公告原文缺失没有稳定进入报告开头。
5. 报告看起来完整，反而掩盖了证据不完整。

## 已抽样证据

### 1. 数据缺口下仍给盘中/做T操作

文件：`reviews/morning/2026-05-18_早盘分析.md`

发现：

- 报告末尾写明：`个股具体价位数据存在缺口（API连接失败），建议开盘后核实`。
- 但同一报告仍输出多只股票的做T策略、支撑位、阻力位、止损条件。

风险：

- 如果价位数据依赖缓存或接口失败后推算，盘中做T建议应默认禁止或降级为观察。
- “建议开盘后核实”放在末尾，无法抵消前文具体操作对用户的诱导。

应改：

- 只要分时/实时价/K线关键接口失败，报告必须进入降级模式。
- 缺分时：禁止做T。
- 缺K线或价位数据：禁止输出精确买卖价。

### 2. 账户风险未知时仍大量输出做T

文件：

- `reviews/morning/2026-05-21_早盘分析.md`
- `reviews/morning/2026-05-22_早盘分析.md`

发现：

- 多只股票给出“正T/反T”、仓位比例、触发条件、止损价。
- 报告没有先确认用户总仓位、单票仓位、浮亏、是否融资、最大承受回撤。

风险：

- 当用户已经处于亏损、焦虑或接近破产语境时，这类建议会放大交易频率和心理负担。
- 做T建议看似风控，实际可能诱导继续交易。

应改：

- 账户风险未知时，所有做T、新开仓、加仓建议必须禁止。
- 只能输出风险管理、减仓条件、观察条件和恢复交易的前提。

### 3. “主力资金”语言过强

抽样位置：

- `reviews/morning/2026-05-19_早盘分析.md`
- `reviews/morning/2026-05-20_早盘分析.md`
- `reviews/morning/2026-05-21_早盘分析.md`
- `reviews/morning/2026-05-22_早盘分析.md`

发现：

- 多处使用“主力出货”“主力大幅流出”“机构出货明显”等强表述。
- 很多表述来自新闻、第三方资金流、东方财富/证券之星口径，未稳定说明算法来源、延迟、是否可复验。

风险：

- 第三方“主力资金”是平台算法，不是交易所事实。
- 把算法资金流写成真实主力意图，会显著误导操作。

应改：

- 改写为“平台资金流口径显示净流出/净流入”。
- 禁止直接写“主力真实出货/吸筹”，除非有多源证据和价格成交验证。

### 4. 外资/北向判断容易越界

抽样位置：

- `reviews/morning/2026-05-14_早盘分析.md`
- `reviews/morning/2026-05-20_早盘分析.md`
- `reviews/morning/2026-05-21_早盘分析.md`
- `reviews/morning/2026-05-22_早盘分析.md`

发现：

- 多处把宏观、美债、北向、外资流向作为关键观察或传导路径。
- 旧报告不稳定标注北向/南向接口是否成功、是否缓存、是否当日实时。

风险：

- 北向/南向接口失败或滞后时，仍判断外资态度，会形成假确定性。

应改：

- 缺北向/南向：不得判断外资态度。
- 使用缓存：必须写缓存时间和影响。

### 5. 新闻和公告边界不足

抽样位置：

- `reviews/morning/2026-05-12_早盘分析.md`
- `reviews/morning/2026-05-22_早盘分析.md`

发现：

- 龙虎榜、机构净卖出、大宗交易、减持等信息进入交易建议。
- 旧报告未稳定要求公告原文、交易所披露链接、新闻源等级。

风险：

- 新闻标题和二手整理可能准确，但不能替代公告原文。
- 龙虎榜和大宗交易是盘后/条件性披露，不能盘中硬推席位行为。

应改：

- 重大事件必须追公告原文。
- 龙虎榜/大宗交易只能作为盘后线索，不能作为盘中做T依据。

## 根因

### 根因一：旧系统把“完整报告”当成“完整证据”

只要报告结构完整，用户就会自然相信分析已经完成核验。但旧机制没有强制要求每个结论绑定数据状态。

### 根因二：数据层和报告层脱节

接口失败、缓存、延迟、空数据，即使在工具输出中出现，也不一定进入报告开头和操作边界。

### 根因三：操作建议默认开启

旧 prompt 要求“明确结论、目标价、止损价”，但没有先判断账户风险、数据资格和是否允许进攻建议。这导致即使证据不足，也会被格式推着输出操作。

### 根因四：对抗审查太晚

审查如果只在报告写完后出现，就很容易变成形式检查。真正应该在分析前触发风险闸门和数据资格判断。

## 立即修复要求

1. 所有报告第一屏必须有“数据状态”和“操作权限闸门”。
2. 缺分时，不做T。
3. 缺K线/实时价，不输出精确买卖价。
4. 缺融资融券，不写融资盘压力。
5. 缺北向/南向，不判断外资态度。
6. 缺公告原文，不把重大消息写成确定事实。
7. 用户账户风险未知且处于亏损/焦虑语境时，禁止进攻建议。
8. 第三方资金流只能写“平台口径”，不得直接写成真实主力意图。
9. 非常规数据必须使用 `alternative_data_clues.insights` 的信号等级和 `follow_up`，不能直接变成买卖依据。
10. 每份报告必须保存可审计路径，并在复盘时验证“建议是否被数据资格允许”。

## 已落实的硬校验

2026-05-22 已将部分要求落入 `skills/stock-skill/skill_runtime/analysis_validation.py`：

- `risk_gate.mode=risk_gate` 时，禁止 `BUY/ADD`、高置信度 `SELL`、`target_price`。
- 风险闸门必须声明 `blocked_actions`，且必须包含 `DO_T` 和 `HIGH_CONFIDENCE_SELL`。
- 缺 `intraday_1m` 时，验证器拒绝做T计划。
- 缺 60/120 日 K 线时，验证器拒绝精确目标价、止损价或入场价。
- 缺 `margin` 时，验证器拒绝融资/融券/杠杆压力结论。
- 缺 `north_south` 时，验证器拒绝北向/南向/外资态度结论。
- 缺 `sector` 时，验证器拒绝“主线/板块退潮/顺应主线”结论。
- 强资金语言如“主力出货/机构出货/主力吸筹”必须包含 `platform_fund_flow_disclaimer`，否则不通过。

新增测试覆盖：

- 风险闸门下仍给 BUY 和目标价，必须失败。
- 缺分时仍给做T计划，必须失败。
- 缺北向/南向仍判断外资态度，必须失败。

验证命令：

```bash
python3 -m unittest skills.stock-skill.tests.test_stock_skill
```

结果：29 项通过。

## 对过去机制的判定

旧机制确实会让人受伤。原因不是它完全没有分析能力，而是它会在证据不足时仍表现得像证据充分。这个问题比单个接口失败更严重。

后续修复不能只补数据源，必须把“能不能给操作建议”放到所有分析之前。
