# 小红书运营总规范

> 状态：ACTIVE
> 适用范围：小红书运营研究、选题判断、方法归档、深复盘
> 当前补充源：今日头条（方法文、案例文）

## 1. 目标

这份规范解决三件事：

1. 小红书运营研究怎么做，才不乱
2. 文档怎么落，才不分叉
3. skill 怎么调用长期文档，才不把知识塞进 skill

## 2. 单一事实源

涉及小红书运营时，优先读取以下文档：

1. `guides/xiaohongshu-ops-spec.md`
2. `guides/xiaohongshu-topic-method.md`
3. `research/xiaohongshu/knowledge/knowledge-canon.md`
4. `research/xiaohongshu/knowledge/error-log.md`

旧文档保留作历史参考，不再充当执行主规范。

## 3. 文档落点

长期稳定内容：

- `guides/`：规范、方法
- `research/xiaohongshu/knowledge/`：稳定知识、错误知识

过程内容：

- `research/xiaohongshu/raw/`：原始样本、原始抓取
- `research/xiaohongshu/analysis/`：分析稿、轻量记录、阶段判断

正式重大任务：

- `tasks/<task_id>-<slug>/`

## 4. 研究分层

默认只分两层，避免过程文件越积越乱：

1. `raw`：原始样本
2. `analysis`：分析整理

命名统一为：

`YYYY-MM-DD-主题.md`

示例：

- `2026-04-30-xhs-topic-scan.md`
- `2026-04-30-agent-hook-brief.md`

## 5. 重大任务升级规则

以下情况视为重大任务：

- 跨来源深研
- 形成正式方法结论
- 需要输出可复用的正式研究结果

规则：

- 轻量运行先落 `research/`
- 一旦形成正式结论，可升级为 task
- 若运行时没有 `task_id`，允许自动建 task 骨架

## 6. 工具分工

小红书相关工作默认按下面分工执行：

- 小红书搜索/网页端：找低粉高赞、爆款标题、开头、发布时间
- 手机端补录：补首句、字数、图片数、评论区高频问题
- 浏览器抓取：留页面摘要、snapshot、来源路径
- 今日头条：补方法文、案例文
- Markdown 文档：沉淀样本、分析、知识卡片、错误日志

## 7. 网页采集边界

只采公开可访问内容。

红线：

- 不绕登录
- 不做高风险抓取
- 不整页搬运进知识库
- 不把单篇内容直接上升成长期规律

遇到登录门槛时：

1. 先提示用户登录
2. 继续处理其他可采部分
3. 明确标出缺口
4. 不轻易停工

## 8. 证据留痕

若使用浏览器或网页抓取工具，必须满足：

- 保留 snapshot 或页面摘要
- 标注采集日期
- 记录来源路径或链接
- 区分“原文事实”和“agent 判断”

未留证据的内容，不进入正式结论。

## 9. 输出原则

默认输出风格：

`结论 -> 证据 -> 行动`

语气要求：

- 操盘手口吻
- 术语首处必须白话解释
- 不空泛
- 不机械
- 不拖成大而全文档

## 10. Skill 协作原则

`xiaohongshu-ops` skill 只负责：

- 识别触发场景
- 指挥流程
- 调用 prompt
- 约束工具使用

不负责：

- 存知识正文
- 存错误知识内容
- 维护平行知识库
