# 小红书选题与运营方法

> 状态：ACTIVE
> 写法原则：平台口味优先，方法短卡片化，避免死模板

## 1. 方法范围

当前只覆盖四个模块：

1. 选题研究
2. 采集归档
3. 知识提炼
4. 复盘纠错

## 2. 选题研究

### 2.1 核心判断

选题是否成立，不用死阈值卡。

改为：

- 先收集样本
- 再用选题判断 prompt 交给大模型判断
- 判断风格固定为“平台口味优先”

### 2.2 固定顺序

1. 搜低粉高赞
2. 看爆款样本
3. 记录原始样本
4. 输入样本表 + 我们的目标
5. 用 prompt 判断“值不值得做”

### 2.3 样本观察重点

优先观察：

- 标题结构
- 第一句话
- 选题角度
- 情绪钩子
- 字数或篇幅
- 评论区用户真正关心什么

### 2.4 我们的目标

输入判断 prompt 时，至少说明：

- 当前账号阶段
- 本次内容目标
- 受众方向
- 更偏热点、方法，还是案例

## 3. 采集归档

### 3.1 平台分工

- 小红书：主平台，负责平台口味判断
- 今日头条：补方法文、案例文

### 3.2 归档原则

原始内容先落 `raw`，分析结论再落 `analysis`。

不要一上来就写长期知识。

### 3.3 样本记录建议

字段不写死，但建议至少覆盖：

- 链接
- 关键词
- 发布时间
- 作者/账号
- 粉丝数
- 点赞/收藏/评论
- 标题
- 第一句话
- 篇幅观察
- 可借鉴点

## 4. 知识提炼

### 4.1 目标

多篇样本、多篇文章，最终只提炼成一份长期知识总稿：

`research/xiaohongshu/knowledge/knowledge-canon.md`

### 4.2 原则

- 简洁优先
- 准确优先
- 去重
- 不逐篇复述
- 不写成长教程

### 4.3 结果形态

长期知识统一写成“短方法卡片”。

卡片字段不强制写死，由 prompt 引导 agent 总结。

## 5. 复盘纠错

### 5.1 错误升级

错误知识一次出错就进入 `error-log.md`。

### 5.2 合并原则

写入前先读取已有案例：

- 有关联：优先补充旧条目
- 无关联：再新增

是否合并，由 agent 分析决定，不靠死规则硬拼。

### 5.3 复盘定位

skill 不做定时器。

它只提供深复盘的方法：

- 看数据
- 看错判
- 看选题偏差
- 看篇幅与开头是否偏离平台口味

## 6. 产出排序

一个完整流程，默认按这个顺序交付：

1. 原始样本
2. 分析稿
3. 结论
4. 必要时更新长期知识
5. 必要时更新错误日志
